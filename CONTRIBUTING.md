# Contributing to metto-data

## Two tracks

1. **Data contributions (no coding needed):** fix facilities, coordinates,
   names, statuses, connections, transfers. See
   [`contributions/README.md`](contributions/README.md) and
   **https://data.metto.ir**. One JSON file per proposal in
   `contributions/pending/`.
2. **Code contributions:** importers, validators, scripts, schemas. TypeScript,
   `pnpm typecheck`, `pnpm validate`, `pnpm test` must pass.

## Iron rules

* **Never touch `upstream-*/`.** Submodules are read-only source material.
  Upstream bugs get fixed upstream (open a PR there); Metto-side corrections
  go in `overrides/`; community fixes go through `contributions/`.
* **Never hand-edit `data/cities/*`.** Those files are generated by
  `pnpm build`. Edit the inputs (importer, overrides, topology, approved
  contributions) and rebuild.
* **One concern per PR:** submodule bump, importer change, new city, or a
  batch of related contributions — never mixed with unrelated refactors.
* **Provenance in the same commit:** submodule bumps must update
  `sources.json` (`pinnedCommit`, `lastSyncedAt`, `stationCount`) and include
  a fresh `pnpm build` + `pnpm validate` run.

## Review process

Maintainers run `pnpm contributions:validate` (schema + references, no dataset
mutation), review `pending/` proposals, move them to `approved/` (with
`review.*`) or `rejected/` (with `review.reason`), then rebuild. Rejections are
kept for history. Spam, PII, or copyrighted third-party content is rejected.
